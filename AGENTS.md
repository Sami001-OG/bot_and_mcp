## Objective
- Single-user, Vercel-deployable Next.js live-trading app in `apps/web`: **Bybit only** (spot + USDT_MAP), TradingView webhooks, MCP server, synchronous order execution, MongoDB/Prisma, single-password auth. Exchange API credentials are stored per-account in MongoDB encrypted at rest — **every bot is created with an exchange API; nothing is hardcoded in `.env`**. User will provide the MongoDB Atlas connection string later (local replica set for now).

## Architecture
- One app: `apps/web` (Next.js 15, App Router, `next start`), plus workspace packages `@platform/database` (Prisma+Mongo), `@platform/security` (encryptSecret/decryptSecret), `@platform/contracts`, `@platform/exchange-core`, `@platform/exchange-adapters` (ccxt), `@platform/trading-core`, `@platform/risk-engine`, `@platform/bot-engine`, `@platform/webhook`, `@platform/commands` (all domain logic). Packages are **bundled into the `.next` build** — after editing any package, rebuild the package dists AND run `next build` again.
- API surface: `/api/auth/login` (APP_PASSWORD), `/api/settings`, `/api/exchange-accounts` (+`/[id]`), `/api/bots` (+`/[id]`, `/[id]/[action]`), `/api/orders`, `/api/portfolio/*`, `/api/webhooks/tradingview/[endpointId]`, `/api/mcp`. UI: `/dashboard`, `/orders`, `/bots`, `/accounts`, `/risk`.
- MCP at `/api/mcp` (Streamable HTTP, JSON-RPC): password via `Authorization: Bearer <MCP_PASSWORD>`; `toolSpecs` in `apps/web/app/api/mcp/tools.ts` (22 tools incl. `listAccounts`, `createBot` requiring `exchangeAccountId`).

## Key Flows / Conventions
- **Exchange accounts**: `packages/commands/src/exchange-accounts.ts` — `createExchangeAccount` (exchange must be `bybit`; first account becomes `isPrimary`), `listExchangeAccounts` (returns `keyPreview` like `LICs****iMMB`, `botCount`, never secrets), `setPrimaryAccount`, `deleteExchangeAccount` (409 `ACCOUNT_IN_USE` if bots reference it), `getAccountSecret(id)` (decrypts `apiSecret` only — `apiKey` stored plaintext), `getPrimaryAccount` (404 `NO_ACCOUNT` if none). API keys are plaintext identifiers; only the **secret** is encrypted.
- **Account binding**: `packages/commands/src/account.ts` — async `getAccountConfig(accountId?)` / `connectToAccount(accountId?)` are DB-backed; env-credential reading was removed. `Bot.exchangeAccountId` + `OrderIntent.exchangeAccountId` (ObjectId) drive everything: `createBot` requires + validates `exchangeAccountId`; `persistOrder` records the bot's account; `executeOrderNow`/`cancelOrderNow`/`resyncOrderNow` use `order.exchangeAccountId`; `parseOrderBody(body, idempotencyKey?, config?)` accepts an optional pre-resolved config (unit-testable without DB).
- **Webhooks**: HMAC-SHA256 hex of the **raw body** as `x-tradingview-signature`; verifier enforces ±5-min timestamp + nonce replay (persisted on the endpoint row). Signal schema (`TradingViewSignalSchema`): `size` is a **decimal STRING**, `timestamp` is an **ISO-8601 STRING** (not epoch), `nonce` ≥12 chars. Signing secret is returned once at bot/endpoint creation and never again. Endpoints are **bot-owned only** — they are created via `createBot`/bot form (never standalone); the admin `/api/webhooks` route + Webhooks page were removed.
- **Bybit clock**: this VM's clock drifts (12s+ skew observed). The adapter now sets ccxt bybit `recvWindow: 30000` + `adjustForTimeDifference: true` (`packages/exchange-adapters/src/index.ts` `connect()`) — never disable; requests fail 10002 otherwise.
- Bot runs: `runBotEvaluation` (in `packages/commands/src/bots.ts`) — connect with the **bot's own account** → live price/equity/positionSide → `buildWebhookOrders` → risk-check (`evaluateOrder`, min-notional skipped when price unresolved) → `persistOrder` + `executeOrderNow` → BotRun STOPPED/ERROR with metrics {price, orders, skipped, notes, positionSide}. Delivery is DELIVERED only if every run succeeded, else FAILED with `routed`/`failed`.
- BullMQ-era rule (still applies to job ids anywhere): custom IDs **cannot contain `:`** — use `-` separators.
